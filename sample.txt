    Use FlowContext.apis[0] already populated
    Call BaselineFacade.computeMultiApiSizing with rssObservedMb from FlowContext
  Call InfraComparisonService.compare(existingInfraConfig, recommendation)
  Store both in FlowContext
  Redirect to /flow/result

## What's Missing / Gaps

Three things were not explicitly covered:

---

**Gap 1 — Repo not passed into GitHubReaderService calls in Flow 3**

In Prompt 13, `readOpenApiSpec(repoName)` and `readInfraConfig(repoName)` are called but the controller needs to pull `repoName` from `FlowContext`. This was implied but not spelled out. Add this clarification prompt:
```
In ReprofilingController and ExistingAppNewApiController, 
wherever GitHubReaderService methods are called, always pass 
FlowContext.getRepoName() as the repoName argument.
Never hardcode or re-ask for the repo name after step2 — 
it lives in FlowContext for the entire session.
```

---

**Gap 2 — FlowContext repoName not shown in UI after selection**

Once the user picks a repo in step2, subsequent pages should confirm which repo they are working on. Add this:
```
In all flow pages after step2 (new-api/form.html, 
reprofiling/step1.html, reprofiling/upload-spec.html),
add a read-only info bar at the top showing:
  "Repository: {repoName}  |  Org: {github.org from config}"
Pull repoName from FlowContext in the controller and add it 
to the model as attribute "selectedRepo" on every GET handler 
after step2.
```

---

**Gap 3 — Flow 1 (New App) has no repo concept but result page should not break**

Flow 1 never sets `repoName` in FlowContext. The result page references `repoName` in the header banner. Add:
```
In ResultController, add repoName to model only if 
FlowContext.getRepoName() is not null.
In flow/result.html, wrap the repo name display with 
th:if="${repoName != null}".
```
